## 4. 固定边界

### 技术与职责

- Unity `2021.3.45f2c1`、URP `12.1.15`；VContainer `1.18.0`、UniTask `2.5.11`、
  MessagePipe `1.8.2`、R3 `1.3.1`；Input System `1.7.0`、Cinemachine `2.10.1`。
- 客户端严格模块化 MVC：`View → Controller → Model/Domain Interface ← Infrastructure`。
  Model/Controller 不引入引擎对象、SQL、Socket 或具体 View；遵守当前 asmdef 边界。
- 复用自研 HFSM 和行为树。行为树只选意图，HFSM 是动作真相；Animator 只单向投影。
- View 只读 PresentationState；离散事实走注入的 MessagePipe 接口。
  UniTask 传递取消，订阅和场景引用随生命周期释放，持久 App Root 不长期保存场景 View。
- 服务端 .NET 10 模块化单体、SqlSugar、MySQL `5.7.26`、库 `NK`。
  不新增 Redis/MQ/容器/监控平台，不安装新包，不迁移到 MVVM/ECS。
- Addressables、HybridCLR、10 人移动展示和共享天气属于 P5，不在 P4 提前引入。

### 网络、资产与存储

- LegacyNetworkV1 的 Socket、AES/KDF、握手、帧、粘包半包、心跳和线程机制冻结。
  仅在具体子任务获授权后，按 ADR-0007 成对追加应用消息/注册/路由。
  当前最高应用号为 66；再次分配前核对双端实际目录，不复用任何已有编号或字段。
- 身份从认证会话取得；写请求携带稳定 RequestId/OrderId，重试复用同一 ID。
  服务端确定价格、随机、奖励与数量。不得暴露客户端任意发奖或任意掉落列表入口。
- 任务经验、任务奖励与成就奖励是不同来源；资产、流水、领取记录和幂等结果必须原子一致。
  不把 UI 点击、本地 MonsterKilledEvent 或“客户端签名”当成服务端验证过的战斗事实。
- 已部署 `0001`–`0010` 保持字节不变。新结构只能追加迁移，扩展优先；
  MySQL 5.7 不依赖 CHECK，不使用不兼容语法。先 dry-run、首次应用，再重复验证。
- 不读取、打印、记录或提交 `.env`、密码、令牌、私钥、连接串及数据库备份内容。
  需要真实本机数据库测试时，沿用已授权的环境注入方式；不输出变量值。

### 5.2 任务模型草案

并说明与既有模块的依赖方向。只设计任务本身，不重写 P1 商店或 P3 结算。

### 5.3 最重要的前置决策：战斗事实如何得到服务端认可

当前战斗运行在 Unity，P3 只接受受信服务端掉落。两者之间仍缺可验证生产链。
必须提出适合 2 GiB 云主机的方案，明确：

1. 怪物实例/出生批次、远征、地图和账号如何对应；服务端能独立核验什么。
2. 攻击、击杀、采集、交互、反击等客户端输入如何验证；哪些只能作为候选事件。
3. 服务端生成 DropEventId、决定奖励；同一击杀不能换 RequestId 重复产出。
4. 死亡、断连结算、迟到事件与领取如何排序并防竞态；已经结算的远征不能追加资产。
5. 重启恢复/幂等记录、时间来源、日志脱敏、数据库写入频率与有界内存预算。

可比较纯规则校验与更完整的服务端模拟，但必须如实说明各自的证据与限制。
**只验证登录身份、事件 ID 唯一或发生间隔，不足以证明怪物确实被击杀。**
不能为方便开发先开放正式“客户端报击杀就发奖”接口，再宣称以后补安全。
开发测试可以由测试程序集构造受信事件，不得留下 Release 可访问的 GM/测试发奖通道。
架构变化先提交候选 ADR，状态为 Proposed；用户确认前不能标为 Accepted 或开始实现。
