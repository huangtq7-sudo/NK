## 3. 低内存部署门禁

- 部署前关闭HeidiSQL与PowerShell ISE，云端只保留MySQL、Host和SSH。
- 可用内存低于400 MiB时部署脚本拒绝切换；守护启动器低于256 MiB时延迟启动Host。
- 云端不安装SDK、不编译、不运行Unity、不并行启动新旧Host。
- 3306、5222和8011继续只监听`127.0.0.1`，公网只保留受限SSH与远程桌面。

## 4. 固定发布顺序

1. 核对内存、GUI进程、计划任务和三个回环监听。
2. 导出数据库dump并核对SHA-256。
3. 校验发布清单、Host包、Migrator包和全部迁移SHA-256。
4. 停止唯一Host，依次执行迁移dry-run、首次迁移和重复迁移。
5. 备份旧Host目录，原子切换新Host，启动单一计划任务实例。
6. 验证`/health/live`、`/health/ready`、Bootstrap `p3-*`门禁、13项能力和配置版本。
7. 从本地SSH隧道完成真实Unity开始、死亡、返回大厅和重复登录检查。
8. 观察可用内存、分页文件和日志；通过后记录发布证据，失败则恢复旧Host目录。

## 5. 暂不自动执行的维护动作

`C:\NarakaDeploy\backups`当前会保留成功切换的previous目录和失败目录。自动清理属于不可逆维护动作；
在用户确认“保留最近多少份”以及至少保留一个已验收回滚版本之前，部署脚本继续只创建备份、不删除备份。
