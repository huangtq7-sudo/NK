# P2.3 正式运行场景人工验收清单

对应阶段：P2.3（正式场景绑定）
自动化部分见 `Tests/EditModeUnity/P23FormalWorldSceneTests.cs` 与 PlayMode 世界流转测试。
决策依据见 [ADR-0020](../ADR/0020-p2-formal-world-scene-binding.md)。

自动化只能证明**结构**是对的：场景里没有第二台相机、没有 Missing Script、
业务流程指的是正式场景而不是灰盒、材质不是粉的。
观感、手感、寻路和镜头必须由人看。**自动化通过不等于 P2.3 关闭。**

## 怎么进

从 `Assets/Scenes/SampleScene.unity` 开始播放，走正常登录流程。
不要直接打开 `Map01_Task` 或 `Map02_Combat` 播放 —— 那样没有持久化 App Root，
玩家、相机与加载界面都不会出现，这是设计如此，不是缺陷。

> 需要服务端：登录要求 SSH 隧道已开、Host 与 MySQL 在跑。
> 隧道没开时登录会停在版本预检，这与本轮改动无关。

## 出生点与传送门位置

地图一的三个关键位置用的是**你确认过的绝对坐标**：

| 对象 | 位置 | 朝向 |
| --- | --- | --- |
| 入口出生点 | (510, 35, 587) | y = -90 |
| 死亡重生点 | (510, 35, 587) | y = -90 |
| 地图二传送门 | (385.1, 36.1, 602.5) | — |

朝向 y = -90 指向 -X，传送门就在 -X 那一侧，所以角色出场时正对着它。

**这些坐标由工具强制应用，每次执行都会被摆回表里的值。**
要调整就改 `P23WorldSceneSetup.AuthoredPlacements` 这张表（或者告诉我新坐标），
在 Unity 里拖动不会留存。这是刻意的：坐标现在有唯一的权威来源。

地图二的怪物生成点仍按地形归一化坐标采样落位，并且**只在它还停在世界原点附近时**
才落位，因此你在 Unity 里调过之后不会被摆回去。

## 如果环境看起来不对

先确认是不是烘焙光照的问题：派生场景沿用第三方源场景的 `LightingDataAsset`。
如果圣殿发平、没有间接光，检查

```
Assets/Aquarius Fantasy - High Elves/Demo Scenes/High Elves Sanctuary/LightingData.asset
```

是否还在。不要重新烘焙 —— 重烘会在项目里生成一份新的光照数据，
而第三方源场景必须保持只读。
