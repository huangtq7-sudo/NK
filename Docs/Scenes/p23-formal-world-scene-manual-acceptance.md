## 加载进度条：自动化证明到哪一步

自动化已经证明的是**状态序列与帧边界**：

- Controller 发出的序列是 0% → 多个中间值 → 99% → 100% → 隐藏，单调不回退；
- 0% 在 `BeginLoad` 之前就已发布，并且已经等过一帧；
- 一次帧等待即使实际花了 1 秒，显示进度也只前进一个步长（不会跳到 50%）；
- 100% 与隐藏之间至少隔一帧；
- PlayMode 里读的是**真实 LoadingView 的 Label 文本**，逐帧采样，
  确认第一个值是 0%、出现 1%–99% 的中间值、出现 100%、单调，
  且场景切到 Map01_Task 之前没有出现过 100%。

**自动化证明不了的**：像素是否真的被画到屏幕上。无图形 CI 没有真实呈现，
`resolvedStyle` 与 Label 文本只能说明 UI 树的状态是对的。
进度条看起来顺不顺、有没有肉眼可见的跳跃，仍然要你在真机上看。

另外：最短显示时长现在以**帧**计（120 帧），不再以秒计。
低帧率机器上加载界面会停留更久 —— 这是"进度条绝不按墙钟跳跃"的代价。

## 出生点与传送门位置

地图一的三个关键位置用的是**你确认过的绝对坐标**：

| 对象 | 位置 | 朝向 |
| --- | --- | --- |
| 入口出生点 | (510, 35, 587) | y = -90 |
| 死亡重生点 | (510, 35, 587) | y = -90 |
| 地图二传送门 | (385.1, 36.1, 602.5) | — |

朝向 y = -90 指向 -X，传送门就在 -X 那一侧，所以角色出场时正对着它。

**这些坐标由工具强制应用，每次执行都会被摆回表里的值。**
要调整就改 `P23WorldSceneSetup.AuthoredPlacements` 这张表（或者告诉我新坐标），
在 Unity 里拖动不会留存。这是刻意的：坐标现在有唯一的权威来源。

地图二的怪物生成点仍按地形归一化坐标采样落位，并且**只在它还停在世界原点附近时**
才落位，因此你在 Unity 里调过之后不会被摆回去。

## 如果环境看起来不对

先确认是不是烘焙光照的问题：派生场景沿用第三方源场景的 `LightingDataAsset`。
如果圣殿发平、没有间接光，检查

```
Assets/Aquarius Fantasy - High Elves/Demo Scenes/High Elves Sanctuary/LightingData.asset
```

是否还在。不要重新烘焙 —— 重烘会在项目里生成一份新的光照数据，
而第三方源场景必须保持只读。
