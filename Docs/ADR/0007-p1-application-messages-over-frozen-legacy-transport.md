# ADR-0007：P1业务消息通过冻结的LegacyNetworkV1适配边界扩展

- 状态：已接受
- 日期：2026-09-07

## 背景

P0已经完成账号注册、登录、连接级认证、配置版本预检与空大厅。新P1需要为账号快照、货币、英雄/兵器/宠物选择、仓库、商店、锻造、抽奖、签到、账号等级奖励、红点、好友和一对一文字聊天提供真实客户端—服务端交互。

LegacyNetworkV1的握手、AES/KDF、帧格式、Protobuf编码机制、粘包半包、心跳、Socket循环和线程模型已经冻结。直接在Controller中操作Socket、复制加密逻辑、信任客户端AccountId，或为了大厅功能重构传输层，都会破坏P0的兼容性与认证边界。另一方面，只保留现有登录消息不足以承载P1业务。

## 决策

P1采用“冻结传输、增量扩展应用契约”的方式：

- LegacyNetworkV1现有传输机制继续冻结，不修改握手、加密与密钥派生、帧布局、Protobuf编码方式、粘包半包处理、心跳、Socket收发、线程派发和连接生命周期。
- 现有协议名、`0–18`协议号、字段编号与线级行为保持不可变；不重命名、不重排、不复用。
- 新业务消息只能成对加入客户端和服务端基础设施适配器。新增具体DTO的类型注册、协议名、未占用协议号与路由映射属于受控的应用适配工作，不代表允许重构传输实现。
- 每个特性在Application层定义自己的Gateway接口和领域命令/结果。Controller依赖特性级Gateway；Domain与Application不得引用Legacy DTO、Socket、AES或数据库实现。
- 客户端所有写请求携带RequestId或OrderId。服务端从已经认证的连接会话注入AccountId，不接受客户端以AccountId选择操作对象，也不信任客户端提交的余额、价格、库存、奖励、强化或抽奖结果。
- 经济、库存、奖励、强化、签到和抽奖由服务端事务与幂等记录保证；重复请求返回首次成功结果。聊天与好友操作同样执行认证、目标校验、屏蔽和频率限制。
- 新协议按P1子阶段小批量加入。每一批必须同时完成序列化/反序列化、注册表、双向路由、认证拒绝、错误码、超时/取消、重复请求、Golden/兼容测试和端到端测试，不能先堆齐全部消息再统一验证。
- Bootstrap继续在业务入口前校验ClientVersion、ConfigVersion和ProtocolVersion。部署含新业务契约的Host时必须同步提升最低客户端版本或配置版本，避免旧客户端进入其不理解的流程。
- P1不新增认证HTTP业务API；HTTP仍只承担既有`GET /bootstrap/config-version`。如果后续希望把业务迁移到HTTPS，必须另立ADR并设计令牌、续期、撤销、CSRF/CORS、限流与部署边界。

## P1交付顺序

1. P1.0：共享契约规则、协议号登记、错误码、幂等规则和数据库迁移。
2. P1.1：账号快照、头像、等级与三种货币。
3. P1.2：英雄、兵器与宠物选择。
4. P1.3：仓库、实例/堆叠物品与装备方案。
5. P1.4：商店、购买事务、货币流水与溢出处理。
6. P1.5：锻造和武器强化。
7. P1.6：抽奖订单、20抽保底与断线结果恢复。
8. P1.7：签到、账号等级奖励与红点。
9. P1.8：好友申请/接受/拒绝/删除/屏蔽、在线状态和一对一文字聊天。
10. P1.9：大厅全入口、重登恢复和服务端权威联合验收。

## 结果

- P0验证过的LegacyNetworkV1线级行为不因P1被重写，新增功能仍通过同一认证连接运行。
- 应用协议可以小步扩展，但每次扩展都增加客户端与服务端同时升级的约束，因此必须由版本预检和自动化兼容测试守门。
- 好友与聊天属于Social模块，不混入Economy模块；P1只实现已确认的最小社交范围。
- 当前大厅UI、静态`--`数据和占位提示不能作为P1完成证据。只有真实服务端数据、事务/幂等、自动化测试与用户人工UI验收同时通过，相关子阶段才可关闭。
- Unity界面布局、素材选择、UXML/USS、场景挂载和Inspector操作继续由用户手工完成；该ADR不授权Codex修改这些内容。
