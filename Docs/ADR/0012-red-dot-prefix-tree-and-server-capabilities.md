# ADR-0012：红点用路径前缀树加版本号，服务端能力声明用于旧云端兼容

- 状态：已接受
- 日期：2026-09-08

## 背景

两个看起来无关的问题在P1里同时出现，但它们有同一种解法形状——**用一个显式的、可比较的状态取代一个隐式的布尔**。

**红点。** 十个大厅入口都可能挂红点，来源分散在签到、抽奖、锻造、成就、账号等级与社交六个模块里。如果每个模块各自控制自己按钮上的一个bool，会出现两类都很难查的bug：玩家点开一次之后红点永久熄灭（因为没人再把它置回true），或者某个按钮永远亮着（因为清除逻辑漏了一条路径）。

**旧云端兼容。** 云端Host仍停在P1.1-A，只认识协议0–20。开发期间新客户端必须还能登录旧云端并进入大厅。如果客户端登录后自动发送新协议，旧Host会把无法识别的消息升级成连接级异常——ADR-0008记录的那次事故正是这样发生的。

## 决策

### 红点：路径前缀树 + Version/SeenVersion

- 红点是一个**独立模块**。它不认识背包、锻造或社交，只认识路径与版本号。
- 节点树就是路径本身，`Lobby/Social/UnreadChat/c42`的祖先由字符串前缀决定，不需要单独维护父子指针：

```
Lobby
├─ Inventory/NewItem
├─ Forge/UpgradeAvailable
├─ Gacha/UnshownResult
├─ SignIn/DailyClaim
├─ SignIn/MilestoneClaim
├─ AccountLevel/ClaimableReward
├─ Achievement/ClaimableReward
├─ Social/FriendRequest
└─ Social/UnreadChat/{ConversationId}
```

- 每个节点存`Version`与`SeenVersion`两个单调递增的整数，**不存bool**。红点亮起的条件是`Version > SeenVersion`。
  - 玩家点开界面时把`SeenVersion`推到当前`Version`；之后业务再推进`Version`，红点自动重新亮起，不需要任何"重新置位"调用。
  - bool做不到这一点：它被下一次读取覆盖，中间到达的新内容就丢了。
- 叶子变脏时只把它自身与祖先的版本往上推，兄弟节点不受影响。标记已读时只清该节点与其子树，祖先按"子树里是否还有未读"重算——因此读完一段会话不会顺手把整个社交入口的红点抹掉。
- 业务模块通过MessagePipe发布`RedDotSourceChanged(path, hasContent)`声明自己有没有内容，红点模块订阅并独自完成聚合。两边**没有任何直接引用**。
- 界面只订阅`RedDotPresentationState`（经R3包装的只读状态），不去问任何业务模块"你有没有可领取"。
- `SeenVersion`持久化到`account_reddot`表，因此跨登录保留。服务端只保存版本对，**不判断红点该不该亮**——那是业务数据说了算。
- 好友的在线绿点/离线灰点**不属于**红点系统：它表达"对方在不在"，不是"有你还没处理的东西"。它留在社交模块自己的展示状态里。
- 没有可领取、没有未读、没有新增时，**不显示任何红点**。

### 服务端能力声明

- Bootstrap的`GET /bootstrap/config-version`响应新增**可选**字段`serverCapabilities`。旧云端Host不返回它。
- 当Bootstrap版本门禁已经匹配但客户端拿不到该字段时，退回`NarakaServerCapabilities.CompatibilityMode`（只含`lobby.account.summary`）。此时注册、登录、账号概要与进入大厅照常可用；点击任何其他入口显示"服务器功能尚未升级"，且**绝不发送未知协议**。能力兼容不绕过ConfigVersion预检。
- 只有当Host声明了对应能力，客户端才会发送该功能的请求。
- `NarakaServerCapabilities`区分两个数组：`Full`是**登记表**，用于校验字符串合法；`Implemented`是**本Host真正实现的能力**。Host只声明后者。声明一个尚未实现的能力比不声明更糟——客户端会因此发送传输层不认识的协议，而兼容门控存在的意义正是避免这件事。
- P1开发期间旧云端曾暂时保持`p0-config-1`，以便验证能力缺失时的兼容模式。完整P1集中发布按ADR-0008把Bootstrap门禁提升为`p1-config-1`；生成配置仍有独立版本号与哈希，两者互不混用。

## 结果

- 新增一个红点来源不需要改动界面代码：发一个事件、给一个路径常量即可。
- 不存在"某个按钮永远挂着红点"：叶子没有内容时祖先会被重算并熄灭，且有测试直接断言这一点。
- P1开发期的预发布客户端在门禁仍为`p0-config-1`时能登录旧云端并进入大厅；测试证明版本匹配而能力字段缺失时兼容模式仍有效，也遍历全部十个入口证明不会发出未知协议。完整P1客户端改用`p1-config-1`，另有回归测试证明它会在预检阶段拒绝旧`p0-config-1`云端。
- 代价是每个红点节点多存一对整数，以及业务模块要记得在状态变化后发一次事件。相比"红点永久熄灭"这类只能靠玩家投诉发现的bug，这个代价是划算的。
