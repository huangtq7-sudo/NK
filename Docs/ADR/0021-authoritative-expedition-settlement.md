# ADR-0021：服务端权威的远征临时资产与幂等结算

- 状态：已接受
- 日期：2026-10-07
- 对应阶段：P3远征闭环

## 背景

P2已完成两张正式运行场景、固定传送门、异步加载、战斗和死亡返回地图一。
P3要把这些本地流程接到服务端权威的远征生命周期。其中最严重的风险是断网、
闪退或重复请求造成重复发放，以及把玩家死亡错当成账号资产清空。

## 决策

1. 每次点击“开始游戏”由服务端创建稳定`ExpeditionId`；存储层保证同一账号最多一个活动远征。
2. 临时资产按`AssetKind + AssetId + Source`聚合。P3只接纳服务端怪物掉落系统产生的记录；
   客户端不能上报任意物品或数量。任务直接奖励不进入临时背包。
3. 玩家死亡只清理当前远征中`MonsterDrop`且尚未结算的临时物品与临时货币，
   写入死亡审计后继续同一远征。账号仓库、账号货币和任务直接奖励不受影响。
4. 从地图一返回大厅是正常结算；连接丢失（断网/闪退）立即走同一结算管道。
   服务器自身故障不调用死亡或连接丢失结算，应依最后成功快照恢复或补偿。
5. 结算必须在同一数据库事务中锁定远征行，合并库存/邮件，写入货币与不可变流水，
   保存`SettlementSummary`并把远征标记为已结算。任一步失败全部回滚。
6. 首次结算成功后，任何重复结算都重放首次`SettlementSummary`，不再计算也不再发放。
   `ExpeditionId + RequestId`是线上审计键，`ExpeditionId`的已结算状态是最终防重保障。
7. `MapId`是远征持久化的业务值，Unity场景名只由`IWorldSceneCatalog`在客户端解析，不写入协议或数据库。

## 实施顺序

1. 纯.NET领域聚合和单元测试。
2. 应用服务与原子存储端口。
3. 只追加的MySQL 5.7迁移与原子存储实现。
4. 断连触发和LegacyNetworkV1之上的业务消息适配。
5. Unity模块化MVC的临时背包、结算摘要与场景流转绑定。

截至2026-10-08，步骤1至3已完成并通过本机MySQL 5.7.26真实验收。迁移器连续两次核对
0001至0010及33张表；自清理远征冒烟覆盖死亡清理、原子结算、仓库溢出转邮件、货币流水和
重复结算重放。真实数据库验收发现并修复了`DATETIME(6)`微秒精度与结算资产读取顺序造成的
首次结果/重放摘要差异。完整服务端CI为387/387，Release构建0警告、0错误。步骤4至5仍未开始。

## 边界

- 不修改冻结的LegacyNetworkV1 Socket/AES/帧格式。
- 不在本ADR里增加新掉落数值、新物品或新玩法。
- 不修改用户手工制作的Unity UI布局。
- 云端仍遵守ADR-0008：P3完成一个可验收的服务端大类后集中部署，不逐步频繁更新低内存云主机。
