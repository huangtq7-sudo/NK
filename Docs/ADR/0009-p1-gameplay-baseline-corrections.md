# ADR-0009：P1玩法基线修正——三种货币、堆叠仓库、必定成功锻造与抽奖五档品质

- 状态：已接受
- 日期：2026-09-08

## 背景

`NARAKA_完整玩法设计.md`与早期任务表里存在若干与用户最新确认不一致的条目：出现过第四种货币"金砖"；仓库同时存在"堆叠物品"与"实例物品"两种模型；锻造带有随机失败概率；抽奖的品质档位与保底规则不明确；成就经验与账号经验混在一起。

这些不一致不是文档笔误。它们会直接变成互相冲突的代码：一个按实例存储的魂玉和一个按ItemId堆叠的魂玉不可能共用同一张表，也不可能共用同一个装备方案；一个"90%成功率"的锻造和一个"必定成功"的锻造在事务边界上完全不同。

## 决策

### 货币

- 全局只有三种货币：铜币（Copper）、幻丝（Silk）、金币（Gold）。**"金砖"这个名字不得出现在任何代码、配置、界面或文档中。**
- 新账号各发1000。三种货币都不能用真实货币购买，P1不做任何支付。
- 铜币是基础流通货币（药品、传送卷轴、基础材料）；幻丝是高级代币（限定物品、稀有材料、锻造石、后期强化）；金币是核心稀有货币，抽奖与特殊物品消耗它。
- 产出与消耗全部走配置。P1只建立发放与消耗能力，真实产出事件（击杀怪物、远征掉落）留到P2/P3，**客户端不伪造任何产出**。

### 兵器

- 长剑与太刀不进仓库、不在商店出售。每个账号每种兵器恰好一把，等级、强化、熟练度与击杀数各自独立并由服务端持久化。
- 兵器使用稳定`WeaponId`，绝不使用列表下标。默认兵器也使用稳定ID。

### 仓库与堆叠

- **所有**仓库物品统一走堆叠数量模型。魂玉与护甲也按`ItemId`堆叠，没有随机词条，没有独立实例。取消"实例物品"这一整个概念。
- 数量是服务端权威整数；每种物品有可配置的`StackLimit`。
- 装备方案引用`ItemId`而不是随机实例ID。已装备的魂玉或护甲至少保留一件：出售或丢弃到会失去所有权时，服务端拒绝并提示先卸下。
- 魂玉战斗装载6格且不允许重名，护甲1格。

### 锻造

- 材料足够时**必定成功**。服务端没有任何随机判定，因此也不存在"强化失败"这一分支。
- 界面不得显示虚假的随机成功率，可以显示"成功率100%"或"必定成功"。
- 必须显示当前值到下一级的预览，例如"攻击力68 → 75"。
- 消耗、武器升级与货币流水在一个事务里完成。重复请求只产生一次强化结果。

### 抽奖

- 品质由低到高固定为：白 → 蓝 → 紫 → 金 → 红。
- 单抽与十连都消耗金币，价格可配置。十连至少包含一个蓝及以上。20抽保底出红；提前出红重置保底计数；保底跨登录保留。
- 服务端先在一个事务里原子完成扣费、随机、发奖与结果持久化，客户端**之后**才播动画。动画被跳过、中断、崩溃或断线时，重新登录必须恢复尚未确认展示的结果。
- **客户端不生成任何随机结果。** 奖池、权重、品质、保底替换规则与奖励数量全部可配置。抽奖不提供任何真实付费权益。

### 账号经验与成就

- 账号经验**只**来自任务。击杀、抽奖、签到、购买、锻造与成就都不得直接增加账号经验。
- 账号等级奖励与成就系统是两套彼此独立的系统。成就必须使用`AchievementXp`与`AchievementLevel`，**绝不写入`AccountXp`**。
- 四个成就分类：冒险历程、战斗大师、锻造大师、财富积累，各自独立配置。
- P1完成成就框架与已有系统能触发的成就；依赖P2战斗与P3远征的成就保持未激活、等待事件源，进度恒为0，**不显示任何编造的进度**。
- 账号等级奖励仍由账号等级解锁并手动领取。

### 签到

- 七日循环，服务器05:00为日界。每个周期允许一次补签，消耗一张可配置的补签卡物品。没有补签卡、没有漏签日或周期内已经补过时拒绝。
- 补签卡是普通可堆叠仓库物品，其产出渠道与价格在配置里而不是代码里。
- 连续签到节点为3/5/7天。**七日主进度与连续次数存为两个独立字段，永不合并。** 补签能点亮格子，但不推进连续次数。
- 签到奖励与连续奖励都需要手动领取，且必须幂等。

### 好友与聊天

- 流程固定为：搜索玩家 → 发送申请 → 接受或拒绝 → 成为好友。
- P1包含：按名搜索、好友申请、接受、拒绝、删除、屏蔽、在线/离线状态、好友申请红点、一对一文字聊天、未读私聊红点、基础限流、文本长度上限与输入校验。
- P1**不包含**：世界频道、群聊、语音、文件传输与玩家之间的交易。
- 表情只走预置文本标记或稳定`EmojiId`，不接受任意文件。

## 结果

- 上述条目与`NARAKA_完整玩法设计.md`中的旧描述冲突时，**以本ADR为准**，并已同步回该文档。
- "实例物品"相关的设计与任务条目作废。任何后续需求若要重新引入随机词条，必须先另开ADR推翻本决策，而不是在实现里悄悄加回来。
- 锻造与抽奖的差异被固定下来：锻造零随机、抽奖全部随机在服务端。两者的客户端都不持有任何概率。
