# ADR-0013：P2 玩家动作基线修正——体力 20、统一左键三段、蓄力单档、Move_F 无无敌帧

- 状态：已接受
- 日期：2026-09-26

## 背景

`NARAKA_完整玩法设计.md` 2.2 版里有三处与 2026-09-26 用户确认不一致的条目：

- 体力上限 60、闪避消耗 20、死亡后体力恢复至 60；
- 鼠标左键横击、右键纵击，两者共享同一套三段连招计数；
- 蓄力分 0.6 / 1.2 / 2.0 三档。

这些不是文档笔误。一个上限 60 消耗 20 的体力条和一个上限 20 消耗 10 的体力条，
在"能冲几次"这件事上完全不同（前者 3 次，后者 2 次），恢复节奏也不同：
每秒恢复 5 点在 60 上限里是 12 秒回满，在 20 上限里是 4 秒。
同理，"左右键共享连招计数"和"只有左键"决定了输入缓存要不要区分来源，
"三档蓄力"和"单档蓄力"决定了蓄力状态要不要在中途产生可观测的分档结果。

## 决策

### 体力

- 名称统一为"体力"，不使用"耐力"等别名。
- 上限 **20**。`Move_F` 快速冲刺消耗 **10**，无冷却。
- 每秒恢复 **5**。`Move_F` 结束 **0.75 秒**后开始恢复；受击后恢复额外暂停 **0.5 秒**（累加，不是覆盖）。
- "结束后才开始恢复"意味着**冲刺进行中也不恢复**。初版只在动作结束时设置延迟，
  于是冲刺途中体力照常回升；冲刺动画只有估计的 0.5 秒时看不出来，
  换成实测的 1.333 秒之后一次冲刺能自己回来 6.7 点，"连续两次冲刺耗尽体力"直接失效。
- 体力不足 10 时拒绝 `Move_F`。拒绝与扣除是同一个原子判断，不存在"先扣再回滚"的中间态。
- 拒绝原因进入只读 `PlayerPresentationState.Rejection`，供后续 HUD 与音效消费。
- 客户端没有任何路径能把体力写成负数或超过上限。
- 死亡重生后体力恢复至最大值 **20**。

### Move_F

- `Move_F` **没有无敌帧，也不提供霸体**。旧版"闪避带短暂无敌帧"的设计作废。
  要重新引入无敌帧必须另开 ADR 推翻本条，而不是在实现里悄悄加回来。
- Shift 判定：按下不足 0.18 秒释放 → `Move_F`；按住达到 0.18 秒且存在 W/S 输入 → Run；
  长按但没有移动输入 → 不进入 Run，也不原地播放跑步动画。
- 进入 `Move_F` 后不会因为继续按住 Shift 自动切换到 Run；冲刺结束后重新按当前输入
  判断 Idle / Walk / Run。

### 普通攻击与蓄力

- 普通攻击统一使用鼠标左键。三段固定顺序：`Attack01` → `AM_Summon` → `Attack02`。
  鼠标右键纵击 **P2 第一阶段不实现**，留待武器与怪物阶段连同"飞行怪只能被纵击命中"一起评估。
- 输入缓存 0.18 秒，连招重置 0.8 秒，第三段结束回到第一段，一次点击只推进一段。
- **提交时机**：普通攻击在"左键释放且按住时长不足蓄力阈值"时提交；
  蓄力在"按住达到 2 秒"时提交。这是本 ADR 唯一能同时满足
  "不足 2 秒释放按短按规则处理"和"不能既普通攻击又蓄力"两条要求的读法。
- 蓄力只实现 **2 秒满档**，到时自动释放 `Attack10`。约 0.6 与 1.2 秒作为
  **预留的视觉分档阈值**留在配置结构里（`ChargeTuning.ReservedTier1Seconds` /
  `ReservedTier2Seconds`），本阶段不产生任何行为差异，也不伪造伤害分档。
- 蓄力期间禁止普通移动，为霸体但仍受伤；死亡可以打断蓄力。

### 霸体

- 蓝色霸体覆盖：第三段普通攻击、蓄力、F 技能、V 技能。
- 霸体只阻止普通受击硬直，不阻止伤害、护甲扣减与死亡。
- 重生保护（3 秒）期间直接免伤。

## 结果

- 上述条目与 `NARAKA_完整玩法设计.md` 旧描述冲突时以本 ADR 为准，相关条目已同步回该文档
  （§4 死亡恢复、§5 输入、§6 整节、§7 攻击与蓄力、§9 两名英雄基础属性）。
- 每一条数值都由 EditMode 测试直接断言，测试即基线：改数值必须同时改测试与玩法文档，
  三者不一致会在本机立刻失败，而不是在游戏里表现为"冲刺次数不对"。
- 右键纵击与三档蓄力不是被删除，而是被明确推迟。重新启用它们时必须回到这份 ADR
  说明与飞行怪判定、武器切换的关系，而不是直接在状态机里加一条分支。
