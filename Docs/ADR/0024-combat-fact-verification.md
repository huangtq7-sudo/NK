# ADR-0024：战斗事实的可信生产链（候选）

- 状态：Proposed（P4.0 提出，用户尚未批准；P4.3 实施前需单独确认）
- 日期：2026-10-11
- 对应阶段：P4.3

## 背景

战斗运行在 Unity 客户端，P3 只接受服务端模块产生的怪物掉落（`ExpeditionService.GrantMonsterDropsAsync`，目前只有测试和冒烟调用）。云主机为 2 vCPU/2 GiB，服务端请求在 Select 循环中同步处理。只验证登录身份、事件 ID 唯一或发生间隔，不足以证明怪物确实被击杀；不能先开放“客户端报击杀就发奖”的接口。

## 候选方案

| 方案 | 做法 | 能防住 | 防不住 | 成本 |
|---|---|---|---|---|
| A 纯规则 | 刷怪上限、时间与速率检查 | 超速刷怪 | 刷怪规则以内的任意伪造击杀 | 极低 |
| **B 推荐：服务端怪物账本 + 命中声明校验** | 服务端按刷怪区规则（20 秒补 1、上限 3）发放怪物实例 ID 并维护血量；客户端每约 250 ms 批量上报命中声明（攻击类型、目标实例、HitId）；服务端用自己的装载与配置计算伤害，检查冷却、节奏与 HitId 去重；血量归零判定击杀，`DropEventId = 远征ID + 怪物实例ID`，经既有 `TryAppendDrops` 写入 | 伪造物品清单、超出刷怪规则的击杀、伤害放大、重放、死亡/结算后追加 | “命中是否真的发生”和位置仍由客户端声称，按合法节奏操作的外挂 | 中：每远征 ≤64 只怪、HitId 环形缓冲 256；只在掉落时写库 |
| C 服务端完整模拟 | 服务端运行物理与 NavMesh | 最强 | — | 需要无头 Unity，2 GiB 主机不可行，不采用 |

## 方案 B 的关键规则（草案）

1. 需要新增“地图进出”报告，让服务端知道玩家在 Map01 还是 Map02；Map01 不发放怪物。
2. 命中声明带“第几条命”（死亡次数）；死亡后迟到的旧命声明一律拒绝；远征已结算则拒绝写入。
3. Host 重启后怪物账本丢失需重新刷怪；已发放掉落按 DropEventId 持久，不会重复。
4. 时间只用服务端单调时钟；日志只记 RequestId、ExpeditionId、实例 ID，不记令牌。
5. 测试可在测试程序集构造受信事件，Release 版本不留 GM/测试发奖通道。
6. 协议号与能力名在实施前按当时双端目录核对后再定（P4.1 已占用 67/68）。

## 状态说明

本 ADR 只记录候选方向，不授权实现。P4.1 的任务目标全部是对话类，不依赖本方案；配置编译器拒绝启用 Kill/Collect 等战斗目标。
