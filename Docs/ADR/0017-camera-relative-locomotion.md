# ADR-0017：移动改为相机相对，取消后退与原地转身

- 状态：已接受
- 日期：2026-09-28

## 背景

[ADR-0013](0013-p2-player-action-baseline.md) 与 `NARAKA_完整玩法设计.md` §5 之前采用的是
"坦克式"控制：W 沿角色当前正前方移动、S 沿正后方移动、A/D 只改变角色朝向而不产生位移。
P2 第一阶段按这套规则实现并通过了自动化验收。

2026-09-28 用户在 Unity 里实际操作之后明确否掉了这套控制：

> WASD 四个方向都是控制角色的移动的，即按下任意的 WASD 键会有向前走的动画，
> 而不是 AD 键控制旋转，并且我也没有 S 键控制后退，只允许使用控制前进的动画。
> 按方向键会改变人物朝向并移动。摄像头以角色为中心、摄像头为半径，
> 鼠标上下左右滑动会改变摄像头的方位，实现仿照永劫无间。

这不是数值调整，而是换一套控制模型。坦克式控制和相机相对控制在三件事上不兼容：
需要几套行进动画（前后两套 vs 只要前进一套）、A/D 产生位移还是只产生旋转、
以及"朝向"由谁决定（玩家的转向键 vs 摄像机方位加输入方向）。

## 决策

采用**相机相对移动**（camera-relative locomotion），即绝大多数第三人称动作游戏的标准模型。

### 移动

- WASD 四个方向都产生移动。方向在**摄像机水平平面**内解释：
  W = 镜头正前方，S = 镜头正后方，A/D = 镜头左右，斜向组合取其夹角方向。
- 目标世界朝向 = 摄像机 Yaw + 输入向量在摄像机平面内的角度（`Atan2(x, y)`）。
- 角色以 `TurnDegreesPerSecond`（默认 **720°/秒**）朝目标方向转，
  转向期间沿**自己当前的朝向**前进。因此一次 180° 反打会看到一个短暂的转身弧线，
  而不是瞬移换向或横向滑步。
- 没有移动输入时不转向：松开按键角色停在当前朝向，不会被镜头拖着回正。
- 斜向输入的模长钳制到 1，否则斜着走会比直走快 41%。
- 行走与奔跑各只有一个速度（默认 5.0 / 7.5 米每秒），四个方向同速。
  旧的 `WalkBackwardSpeed` / `RunBackwardSpeed` 一并删除。

### 动画

- 只使用前进动画。`Walk_F` 对应 `Walk`，`Run_F` 对应 `Run`。
- **`Walk_B` 与 `Run_B` 不再被任何状态引用**。它们的 `.meta` 已恢复默认导入设置，
  因此本阶段改动过的动画 `.meta` 从 5 个减少到 3 个：
  `AM_Stand1_Action03`、`Walk_F`、`Run_F`。文件本身保留在磁盘上未删除。
- `LocomotionState` 与 `PlayerAnimation` 里的 `WalkForward` / `WalkBackward` /
  `RunForward` / `RunBackward` 四个枚举值合并为 `Walk` / `Run`。
  Animator Controller 从 20 个 State 减为 18 个，装配工具会主动删除孤儿 State ——
  一个投影层无法寻址的 State 留在图里只会让人误以为它还在被使用。

### 奔跑反向

`Run_Turnback` 保留，但判定从"前后输入符号翻转"改为**角度阈值**：

- 新的目标世界朝向与上一次相差 ≥ `RunTurnbackAngleThresholdDegrees`（默认 **135°**）；
- 且两次输入之间的空档不超过 `RunTurnbackInputWindowSeconds`（默认 0.25 秒）——
  松开方向键停一会儿再按反方向属于重新起步，不播反向动作；
- 且当前处于 Run。

小角度转向（例如 W 改成 W+D 的 45°）只是普通转身，不播反向动作。

### 摄像机

结构与 [ADR-0014](0014-p2-input-system-and-cinemachine.md) 描述的一致，本轮补三件事：

1. **首次绑定时镜头从角色背后起步**（`Rebind` 里把 Yaw 对齐到角色朝向），
   而不是从一个与角色无关的初始方位。
2. **虚拟相机随目标启停**：没有角色时关闭，大厅仍由场景自己的 Main Camera 取景。
3. **战斗场景锁定并隐藏鼠标指针**（`Cursor.lockState = Locked`）。
   这是实际操作里才暴露出来的问题：指针自由时一旦移出画面，鼠标位移就归零，
   镜头会莫名停转。锁定只在"已绑定角色且视角可用"时生效——大厅没有角色，
   指针必须保持可用，否则玩家点不到任何按钮。出场动画与死亡期间也会解锁。
   `ThirdPersonCameraRig.lockCursorDuringGameplay` 可以关掉这个行为。

摄像机与角色的关系没变，并且这条保证被 PlayMode 测试直接断言：
轴心不是角色的子物体，它只取角色的位置不取旋转，因此鼠标转镜头不会旋转角色，
角色转身也不会把镜头拖着转。

### 业务层与摄像机的边界

状态机需要知道"现在镜头朝哪"，但不能知道 Cinemachine 或 Transform 的存在。
为此在 Controller 层新增一个只读接口：

```csharp
public interface ICameraOrientation { float Yaw { get; } }
```

`ThirdPersonCameraRig`（Infrastructure）实现它。`PlayerCharacterView` 每帧把
摄像机 Yaw 与角色当前 Yaw 一并填进 `PlayerInputFrame`，状态机据此算出转向量与速度。
`PlayerInputFrame` 仍然是纯数据，EditMode 里可以直接构造任意镜头/朝向组合来断言。

没有绑定摄像机实现时退回使用角色自身朝向，移动变成角色相对：能操作，
不会因为缺少摄像机就完全动不了。

## 结果

- 与 `NARAKA_完整玩法设计.md` §5 旧描述冲突时以本 ADR 为准，条目已同步回该文档。
  ADR-0013 关于体力、攻击键与蓄力的结论不受影响，只有它引用的移动规则被本 ADR 取代。
- `Walk_B` / `Run_B` 不是被删除，而是不再被引用。如果将来要做锁定视角下的横移与后退，
  需要回到这份 ADR 说明与 `Run_Turnback`、A/D 语义的关系，而不是直接加两个状态。
- 720°/秒 与 135° 都是我给的初始手感值，不是测量结果。它们在
  `PlayerTuning.asset` 里可调，需要你实际试过再定。
- 新增 EditMode 覆盖：四个方向都移动且共用前进动画、目标朝向随镜头旋转、
  转向受角速度限制并走最短路径、无移动输入时不转向、四方向同速、斜向输入归一化、
  小角度转向不触发反向动作。PlayMode 新增：四个方向键都既转向又移动且朝向相对镜头、
  镜头转开后按 W 角色朝镜头新方向走。
